# CLI Event Triage Design Notes

## Context & Motivation

Prototyping a CLI tool (`cli/triage.py`) to triage and "thread" through the logged events feed of a Trail project, deciding which events to retain in the project record and which to drop.

---

## Agreed Layout & Visual Architecture

### 1. Three Equal Panes (Top)
- **Left Pane (`Accepted`):** Events accepted into the trail.
- **Center Pane (`Pending`):** Incoming live queue of events awaiting confirmation.
- **Right Pane (`Declined`):** Events marked for rejection / removal.
- **Equal Widths:** The three columns are divided equally across the terminal width.
- **Strict Ordering:** Events preserve their original chronological/sequence index across all panes. (e.g. accepting #5 then #1 still lists #1 above #5; accepting #3 inserts it between them).
- **Flat Structure:** For initial prototyping, all events are treated flat (nested sub-node selection is deferred).

### 2. Bottom Drawer (Attributes Inspector)
- A persistent bottom pane spanning the full terminal width.
- Displays full properties, parameters, file paths, and metadata for the currently focused event.

---

## Interaction & Control Scheme

### Keybindings
- **`y` / `n` (Decisions):**
  - In `Pending`: `y` accepts the active event (moves left); `n` declines it (moves right).
  - In `Accepted`: `n` revokes acceptance (moves back to `Pending` or `Declined`).
  - In `Declined`: `y` restores the event (moves back to `Pending` or `Accepted`).
- **`←` / `→` (Pane Navigation):**
  - Moves cursor focus between `Accepted`, `Pending`, and `Declined` panes.
- **`↑` / `↓` (Event Navigation):**
  - Moves cursor up and down within the active pane's list. Moving past an event in `Pending` acts as skip/defer without requiring a separate key.

### Mouse Ergonomics
- **Mousewheel:** Active on each pane to scroll up/down without changing keyboard focus.
- **Click & Drag:** Reserved for standard terminal text selection and copy/paste.
- **No Draggable Splitters:** Avoids intercepting mouse click/drag events, preserving native Konsole / Yakuake selection behavior.

---

## Live Feed & Focus Mechanics

- **Streaming Ingestion:** Consumes events live as they occur via `trail.events.watch()` (async iterator using `asyncio.Event` notification).
- **Cursor Stability / Tail Follow:**
  - If the cursor is positioned at the latest event (top/tail of stack), incoming events automatically advance the cursor to stay pinned to the new tail.
  - If the cursor is focused on an earlier event, focus remains pinned to that specific event (tracked by `event.id`), while new events append quietly below without displacing the view.

---

## State Lifecycle & Finalization

- **Default State:** Events are unaccepted by default (`event.is_accepted = False`).
- **Session Triage:** Decisions remain tentative in memory while triage is open.
- **`Enter` (Finalize):**
  - Commits decisions.
  - Accepted events receive `event.is_accepted = True`.
  - Declined events are dropped from the data structures / log.
- **`Esc` (Reset):** Resets unfinalized session choices back to `Pending`.
- **`Esc` twice (Exit):** Exits the triage interface without applying or persisting changes.

---

## Open Considerations for the Plan

1. **Cross-Process vs. In-Process Live Watching:**
   - `trail.events.watch()` operates directly in-process via asyncio.
   - For an independent CLI command (`trail triage`) monitoring events generated by external tools (e.g., Jupyter notebook sessions), determine the synchronization mechanism (file-tailing `.trail/events.jsonl` vs. Unix domain socket / IPC).
2. **Persistence & Schema Impact:**
   - Confirm addition of `is_accepted: bool` to the `Event` dataclass in `src/trail/event.py`.
   - Define exact persistence behavior for dropped events (soft-delete vs. physical purge from `jsonl`).
3. **Terminal Geometry in Dropdown Terminals:**
   - Handle resize events gracefully if invoked in dropdown / scratchpad terminals (e.g. Yakuake).
